# The rail gate — what a rail owes the spine

[Ticket](../tickets/13-the-rail-gate.md) · ruled 2026-08-13

A rail is a **pure function returning offers**, never lines; the gate (`src/core/gate.ts`) is the
spine's **sole writer** of quantity lines — the register door's sibling, where the guard is a
constraint, not a helper a rail may decline to call. "Done" is the rail's return type, in three
tiers: `PARTIAL_UNDECLARED`, a null calibration and prose provenance are **unrepresentable**; both
basis roll-ups, the attribute roles, the refusal cause and the selected algebra are **gate-derived,
never rail-supplied**; and eleven runtime checks run once for all rails — including that the
**formula re-evaluates to the value** in decimal, which makes `identity.md` §6's audit string
checked rather than decorative. Absence is never transmitted: the scope register is a **query**,
`NOT_ESTABLISHED` is its fall-through arm, **nothing writes it**, and a rail's deferral type has no
cause field — the one-way valve is a missing channel, not a guard. `INGESTION_TRUNCATED` /
`ENTITY_TYPE_UNHANDLED` are **ingestion's**, off the artifact's counters, so a rail cannot dress
*code nobody wrote* as *a cap you raise*. Selection is **two independent total code-owned maps on
the kind axis** (kind → discipline, kind → algebra) over a code-owned **`bears` relation on
`(class × kind)`** — independent because one architectural discipline serves two algebras. A hard
block has **two reaches**: impugn the number → row survives with no quantity; impugn the scope's
existence → the object is severed from bill reach. The guardrail is made falsifiable: the gate
ships with a **synthetic face-shaped rail in its own suite, before the face rail exists**, asserting
six member-shaped assumptions it may not make (uniqueness is `(object × kind × level)`; no branch
on element type; provenance is a **set** of citations; inputs resolve through a second object;
zero-offer rails are lawful; whole-subject deferral is lawful). Amends `measurement-rules.md` §8
and `quantity-contract.md` §2/§4. Rejected: a `validateLine` helper each rail calls (rail-authored
done in a spine hat), a materialised `scope_rows` table (one `INSERT` is a silent exclusion with no
actor), rails declaring their own kinds, and lifting the gate when the face rail arrives — the
accidental refactor, which has no failing state. **Found in passing:
`DISCIPLINE_NOT_AUTHORITATIVE` is documented in `enums.ts` as a *door* refusal and is emitted
nowhere — the door never sees a kind; it is a gate refusal.**
