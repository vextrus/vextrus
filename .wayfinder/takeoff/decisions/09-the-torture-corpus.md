# The torture corpus — the gate

[Ticket](../tickets/09-the-torture-corpus.md) · ruled 2026-08-13

The corpus is a **framed census**, framed now and filled by the rails. Each case declares a seam
terminus and a boundary terminus that ratchets outward; assertions stay ordinary pytest/vitest
tests bound by a committed index; fixtures are micro per case with composites frozen by exception;
the index enumerates **undecided** defects too, and an `undecided` entry expires when its ticket
closes. Expectation (`ruled`/`undecided`) and implementation (`asserted`/`pending`) are two axes,
never one. All 17 candidates admitted, 4 added (wrong-selection, topology's refusal, absent scale,
malformed face outline), lakh/crore misgrouping ruled out. One lane inside `verify`, 20s budget
reported not enforced. Rejected: seam-only assertions, a manifest DSL, a corpus lane outside the
contract, and a failing time guard. **Found in passing: the DXF byte-pin is currently false** —
committed fixtures are CRLF, Linux regenerates LF, and nothing asserts it.

**Amended 2026-08-13:** the index is a **directory, one file per case**, not one file. Every rail
appends to it, so one file is nine conflicts across ten parallel rails — the structure measured to
have caused six of seven merge conflicts in the first wave, and worse here because a hand-resolved
conflict in a machine-read census can silently drop a case. Nothing else in ruling 3 changes: the
schema, validators, both binding directions, the ratchet and `undecided` expiry all work over a
glob.
